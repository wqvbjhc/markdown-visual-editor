# 平台导出规则（公众号 / 头条号）

> 平台兼容任务时参考。项目总规则见根 `CLAUDE.md`。

## 核心原则
公众号 / 头条号编辑器接受富文本，靠 `text/html` 内联样式撑排版。但平台会重排 HTML、丢 CSS 语义、清洗原生 list/anchor。必须假设：
- HTML 结构可能被重排
- CSS 语义可能丢失
- 原生 list/anchor 行为可能失效

「浏览器里能工作」≠「平台 paste 后能工作」。

## 排查顺序（平台兼容问题）
1. **先抓「目标平台最终收到的 HTML」或等价证据**（原始解析 HTML / 平台专属导出 HTML / 目标平台粘贴截图），不要只靠源码推断。
2. 再拆层：解析层 / 导出结构层 / 平台 paste 重排层 / CSS 布局层。一个现象可能跨多层，别先赌一层是根因。
3. 优先选「最不依赖平台语义」的导出结构。
4. 测试跟随最终策略（非早期假设）。策略从「保留原生语义」切到「显式 block 结构」时，测试同步切断言。

## 头条外链规则
头条文章支持外链，但不能假设「普通 HTML `<a>` 粘贴就保留链接属性」。
1. 头条专属复制/导出链路**单独兼容**，不当全局 HTML 问题。
2. 修复检查：`applyToutiaoStyles()` 输出链接形式 / `prepareClipboardHtml()` 最终 HTML/text / 头条 paste 是否清洗 `<a>`。
3. 预览正常 ≠ 复制到头条正常（预览、剪贴板、头条粘贴三层不同链路）。
4. 无证据前**别**把正文所有超链接降级纯文本 URL（破坏阅读）。先验证复制前最终 HTML 链接是否在、头条是否支持另一种可点击形式。
5. **别**为头条放宽全局 sanitization，头条兼容限制在头条专属链路内。
6. 证据证明头条不支持 pasted `<a>` → 改内联纯文本 URL，**不要**用新 `<span>`/block 包装（易引入换行/段落错位）。

## 头条嵌套列表规则
1. 「有序列表 + 嵌套无序列表」pasted HTML **不只依赖原生 `<ol>` marker**：顶层序号显式写入导出结构（幂等，防重排成 1），否则平台 paste 后顶层项都重算成 1。
2. 嵌套列表 paste 重排不只顶层 `<ol>`，内层 `<ul>/<li>` 也可能被解释成编号流。顶层序号和内层 bullet 都关键时，两层 list 语义都改显式 block：顶层 `1.`/`2.`，内层 `•` 行。
3. 显式编号**不依赖 `display:flex` 横排**「编号 + 正文」（paste 后平台可能不保留布局语义，编号单独占一行）。把编号 prepend 到正文第一段，共用文本流。
4. 列表导出测试：微信和头条**不同平台**。微信可断言原生 ordered-list marker；头条若改 block 显式编号，测试按头条真实导出结构断言，不沿用「保留原生 decimal marker」旧假设。

## 平台限制参考
头条号编辑器对 HTML/CSS 支持严格：
- `class` 可能被剥离 → 导出依赖内联样式
- `<style>` 可能被过滤 → 外部/页面级样式不可靠
- 部分 CSS 属性失效（颜色/定位/垂直对齐）
- SVG / Mermaid 支持有限

建议：数学公式/复杂图表多时优先公众号渠道；头条发布前先在目标平台编辑器实际粘贴验证。
